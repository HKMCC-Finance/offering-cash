Cash — a real two-offering count

20 min

This is the reported 2차 헌금 problem. The goal is not just "does it work" but capturing both PDFs so the machine's actual behaviour is on record.

Watch for

Open both PDFs side by side and answer one question: is the second PDF cumulative (1차 + 2차) or standalone? The whole subtraction rests on it being cumulative. If it is standalone, the app will now stop with a "기계가 초기화된 것으로 보입니다" warning rather than writing negative quantities — that warning appearing is a correct result, and tells us the fix needs inverting.

03

Checks — scan order

15 min

Before feeding anything into the scanner, write down the check numbers in the order you feed them. That handwritten list is the ground truth for this test.

python src/check_scan.py --img_dir <scan folder> --report_file <report.xlsx>

The report rows should match your handwritten list top to bottom. If they don't, the scanner isn't stamping file times in scan order — try the alternatives and tell me which one matches:

python src/check_scan.py ... --order filename
python src/check_scan.py ... --order checknum
04

Checks — accuracy baseline

30 min

This is the step that turns "roughly 30% wrong" into something measurable. Use a real batch — 100 checks if you have them, 20 if you don't.

After the run, open the review sheet written next to the report (<report>_검토.xlsx). It lists every check with the raw OCR text, both amount reads, and why each row was flagged.

Building the truth file

Go down the review sheet and correct the 발행자 and 금액 columns by eye. Then save it as truth.csv with just three columns, renamed:

filename,name,amount
DEP_1043_Front.tif,John Smith,125.00
DEP_207_Front.tif,Mary Kim,20.00

That file is the durable asset here — every future model comparison runs against it:

python src/benchmark_ocr.py --img_dir <scans> --truth truth.csv --backend legacy
Check first

If amount accuracy comes back near zero, the region boxes in src/check_rois.json are cropping the wrong part of your scans. Open one .tif, note roughly where the $ box and the written-amount line fall as a fraction of the image, and send me the numbers — those defaults are standard-layout estimates, not measured from your scanner.

05

수표정리 summary and printing

10 min

Using the summary block position you noted in step 1 — say it starts at row 20, column I:

python src/check_scan.py ... --summary-anchor 20,9 --print-layout

Predefined rows ($5 / $10 / $20 / $25 / $50 / $100) should always appear even at zero, with any other amount appended below the $100 row in ascending order.
